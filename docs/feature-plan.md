## 0. Правила работы

1. Сначала прочитай `CLAUDE.md` и `docs/MAP.md`. Читай только нужные участки файлов.
2. **Правила игры — только в `shared/`** (движок, данные, ИИ-логика). Сервер остаётся generic: он
   хранит, рассылает, считает время и шлёт сообщения бота, но не решает, что можно делать в игре.
3. Баланс существующих юнитов/построек/техов **не трогать**. Новые числа (события, ИИ-пороги) — в новых
   файлах данных, одной таблицей, чтобы их было легко крутить.
4. После каждого этапа:
   ```bash
   npm run typecheck
   npm run smoke
   ```
   Оба должны пройти. Новые проверки — функцией `checkXxx()` в `scripts/smoke.ts` + вызов в конце файла
   (список вызовов сейчас `:2058-2091`).
5. **Не коммить, не деплой на прод** (`ssh peepuy`), не трогай `.env` на сервере без явной просьбы.
6. Каждое новое поле `GameState`/`Player`/`GameSettings` — **необязательное или с дефолтом в
   `normalizeState`** (этап 2): сохранённые до обновления партии должны загружаться.
7. Всё, что добавляется в `GameState`, проверь на утечку через туман: если поле раскрывает чужие
   дела — маскируй в `vision.ts maskStateFor` (как `resources`).
8. Стиль — как в окружающем коде: TypeScript, ESM-импорты с `.js` в `shared/` и `server/`,
   комментарии по-русски, коротко. Новые входящие действия — через `validate.ts` (`parseGameAction`/`parseLobbyAction`),
   новые socket-события — через `safe()`.
9. Решения, помеченные **«по умолчанию»**, приняты за пользователя; если он ответит иначе — поменяй.

## Этап 1. Журнал не должен пробивать туман войны (пункт 1)

**Проблема.** `log()` (`engine.ts:487`) пишет в общий `state.log`, а `maskStateFor` (`vision.ts:140`) журнал
не фильтрует. Соперник видит «X нанимает 10 × Тяжёлая конница», «X изучает Атака», бои в тумане, голод.

### 1.1. Типы (`types.ts:117 LogEntry`)
```ts
export interface LogEntry {
  round: number;
  text: string;
  /** Кому видна запись. undefined — всем (публичные новости). */
  seenBy?: string[];
  /** Клетка события — клиент по тапу центрирует карту. */
  at?: Coord;
}
```

### 1.2. Движок
- `log(state, text, opts?: { actors?: string[]; at?: Coord[]; public?: boolean })`.
  `seenBy = actors ∪ { живые игроки p : какая-то клетка из at видна p (canWatchTile) }`.
  Если `public` или туман выключен (`settings.fogOfWar === false`) — `seenBy` не ставить.
  `entry.at` = первая координата из `at`.
- Считать свидетелей **после** изменения клеток (владелец сменился — он тоже видит).
- `canWatchTile` импортировать из `vision.ts` (он не импортирует `engine.ts`, цикла нет).
- Разметка всех вызовов `log(...)` (строки на 2026-09-29):

## Этап 2. Сохранение партий на диск (пункт 2)

**Решение по умолчанию:** JSON-файлы, без SQLite (не нужен нативный модуль на сервере, объёмы маленькие).

### 2.1. `shared/src/engine.ts` → `normalizeState(state: GameState): GameState`
Дозаполняет отсутствующие поля дефолтами (все поля, добавленные этим планом: `settings.turnMinutes`,
`settings.randomEvents`, `settings.diplomacy`, `history`, `player.stats`, `diplomacy`, …). Вызывать при
загрузке. Каждый следующий этап дописывает сюда свои поля.

### 2.2. Новый `server/src/storage.ts`
- Каталог `DATA_DIR` (env, по умолчанию `<root>/data`), файл `rooms.json`:
  `{ version: 1, savedAt, rooms: [{ state, updatedAt, turnDeadline? }] }`.
- `markDirty(code)` — вызывать после каждого успешного изменения (game:action, lobby-действия, join/leave,
  sweep, таймер, ИИ). Проще всего — внутри `pushStateSafe`, там уже проходят все изменения.
- Раз в 5 с, если есть грязные комнаты, — запись **атомарно**: во временный файл → `fs.renameSync`.
- `SIGTERM`/`SIGINT` (systemd restart) → синхронное сохранение → `process.exit(0)`.
- Загрузка при старте (`rooms.ts loadRooms()`): `normalizeState`, всем людям `connected = false`,
  `offlineSince` = сейчас (чтобы офлайн-пропуск не сработал мгновенно). Битый файл → переименовать
  в `rooms.broken-<ts>.json`, стартовать пустым, громко написать в лог.
- `data/` добавить в `.gitignore`.

### 2.3. Время жизни комнат (`rooms.ts:4-5`)
С асинхронными партиями 6 ч мало. **По умолчанию:** лобби — 30 мин без людей / 6 ч; идущая партия —
7 дней без действий; законченная — 24 ч (чтобы успели посмотреть статистику и нажать «Реванш»).

### 2.4. Проверки
- `checkNormalizeOldState`: состояние без новых полей → `normalizeState` → `applyAction` работает.
- Ручная: запустить `npm run dev`, начать партию, `Ctrl+C`, запустить снова → партия на месте, ход тот же.

## Этап 3. Таймер хода (пункт 9)

**Сейчас:** офлайн-игрок пропускает ход через 3 мин (`TURN_SKIP_OFFLINE_MS`, `index.ts:34`). Для
асинхронной игры (походил утром, соперник вечером) это убивает партию.

### 3.1. Настройка (`types.ts GameSettings`, `config.ts defaultGameSettings`, `sanitizeSettings`)
`turnMinutes: 0 | 2 | 5 | 60 | 1440`:

| Значение | Режим |
|---|---|
| 0 (по умолч.) | как сейчас: без лимита, офлайн пропускает через 3 мин |
| 2, 5 | блиц: ход сгорает по таймеру, даже если игрок онлайн |
| 60, 1440 | асинхронно: ход сгорает по таймеру, офлайн-правило 3 мин **не действует** |

### 3.2. Сервер
- `GameState.turnDeadline?: number | null` (мс). Ставит **сервер** (время — не правило игры):
  новый `server/src/turnClock.ts`, `syncTurnClock(state, now)` — если сменился `(round, turnIndex)`,
  ставит `deadline = now + turnMinutes·60 000` (или `null` при 0). Вызывать там же, где `markDirty`.
- `sweep()`: если `turnDeadline` прошёл → `applyAction(state, current.id, {type:'endTurn'})`,
  лог «X не успел — ход завершён» (публично). Если висит `pendingSquare` — сначала автоответ обороны.
- При `turnMinutes >= 60` ветку офлайн-пропуска в `sweep` (`index.ts:320-330`) пропускать.
- После загрузки с диска: если дедлайн уже прошёл пока сервер лежал → `now + min(5 мин, turnMinutes)`.

### 3.3. Клиент
- Лобби: выбор «Время на ход» (Без лимита / 2 мин / 5 мин / 1 час / 24 часа) рядом с другими настройками.
- Верхняя панель: обратный отсчёт до `turnDeadline` (мм:сс или «ч ч»), последние 20 % — красным +
  `haptic('warning')` один раз.

### 3.4. Проверки
Правила таймера на сервере — ручная проверка с `turnMinutes: 2`; в `smoke.ts` — `sanitizeSettings`
пропускает только разрешённые значения.

## Этап 4. Уведомления бота: «Ваш ход» и напоминание (пункты 3, 4)

### 4.1. Реестр пользователей `server/src/users.ts`
`{ id, name, canNotify: boolean, notify: boolean, lastTurnMsg?: {chatId, messageId} }`, хранится в
`data/users.json` тем же механизмом, что комнаты. Заполняется: при входе сокета (auth) и при любой
команде бота. `allows_write_to_pm` из `initData.user` → `canNotify`.

### 4.2. Разрешение писать в личку
Бот может писать только тем, кто нажимал /start или дал разрешение. В клиенте (`telegram.ts`) —
`requestWriteAccess()`; вызвать один раз в лобби при входе в партию, если `canNotify === false`
(флаг сервер отдаёт в новом событии `me`). Ошибка 403 от Telegram → `canNotify = false`, больше не слать.

### 4.3. `server/src/notify.ts`
- `onStateChanged(state)` — вызывать из того же места, что `markDirty`. Держит
  `lastNotified: Map<room, "round:turnIndex">`.
- **Ваш ход**: если сменился текущий игрок, он человек (не `hotseat:`, не `ai:`), не в соло-режиме
  и у него **нет сокета в этой комнате** → сообщение:
  `⚔️ Ваш ход — партия ABCDE, раунд 5. Время: до 18:40` + кнопка «🎮 Открыть игру» (`web_app` с `?room=`).
  Прошлое сообщение «ваш ход» этой партии удалять (`deleteMessage`), чтобы не копились.
- **Напоминание** (пункт 4), один раз за ход, если игрок не походил и нет сокета:
  - `turnMinutes = 0`: за 1 мин до офлайн-пропуска (через 2 мин офлайна);
  - 60 → за 15 мин; 1440 → за 2 ч; блиц 2/5 — не напоминать.
  Текст: `⏳ Через 15 мин ход в ABCDE будет пропущен`.
- **Каре** (пункт 3 расширение): если защитник онлайн, но вкладка свёрнута, ничего не делаем — сервер
  и так решит за 60 с.
- Нет `BOT_TOKEN` (локально) → всё в `console.log('[notify] …')`.
- Очередь отправки: не больше ~20 сообщений/с (лимит Telegram 30).
- Команда бота `/notify on|off` → `users.notify`.

### 4.4. Проверки
Ручная: два dev-игрока, один закрывает вкладку → в логе сервера `[notify] ваш ход …`; с настоящим ботом —
сообщение приходит, кнопка открывает нужную партию, старое сообщение удаляется.

## Этап 8. Случайные события (пункт 10)

### 8.1. Настройки
`settings.randomEvents: boolean` (по умолч. `true`), в лобби переключатель «Случайные события».
**По умолчанию** без частоты; при желании позже — `eventRate: 'rare'|'normal'|'often'`.

### 8.2. Механика (`shared/src/events.ts` — данные, `engine.ts` — применение)
- Бросок в `beginTurn` после дохода, **для каждого игрока отдельно**, из `nextRandom` (детерминированно).
- Не раньше 3-го раунда; шанс 25 % за ход; после события — пауза 2 хода (`player.eventCooldown`).
- **Разные для каждого**: у события есть `condition(state, player)` (есть шахта, есть лес, армия ≥ 10…)
  и вес. Вес зависит от места игрока по очкам: отстающим ×1.5 к хорошим событиям, лидеру ×1.5
  к плохим — мягкая подтяжка отстающих.
- Недавнее событие не повторяется у того же игрока 5 раундов (`player.recentEvents`).
- Длительные эффекты — `player.effects?: { id, turnsLeft, incomeMul?, attackMul?, researchDiscount? }[]`,
  учитываются в `computeIncome`, `attackMultiplier`, `techCost`, тикают в `beginTurn`.
- **События с выбором**: `player.pendingEvent`, новое действие `{ type: 'eventChoice'; choice: 0 | 1 }`
  (без траты ⚡). Если игрок не ответил до конца хода — применяется вариант 0 («отказаться»).
- Запись в журнал — **только игроку** (этап 1), кроме событий, меняющих карту (пожар) — их видят свидетели.
- Названия подстраивать под эпоху через `flavorOf` там, где есть разница (наёмники, пушки/катапульты).

### 8.3. Список событий (стартовый, числа — в `events.ts` одной таблицей)

| # | Событие | Условие | Эффект | Тон |
|---|---|---|---|---|
| 1 | Богатый урожай | ≥1 ферма или ≥3 равнины | +50 % еды от дохода сразу | + |
| 2 | Неурожай | ≥1 ферма | −30 % еды 2 хода | − |

## Этап 9. Дипломатия (пункт 8)

### 9.1. Данные
- `settings.diplomacy: boolean` (по умолч. `true`), переключатель в лобби.
- `GameState.relations?: Record<"idA|idB" (сортированно), { kind: 'war'|'truce'|'alliance'; until?: number; breakAt?: number }>`
  (нет записи = война).
- `GameState.proposals?: { id, from, to, kind: 'truce'|'alliance', rounds?: 3|5|10, round }[]`.

### 9.2. Действия (`GameAction`, без траты ⚡, **можно не в свой ход**)
`propose {to, kind, rounds?}`, `acceptProposal {id}`, `declineProposal {id}`, `breakTreaty {with}`.
В `applyAction` проверка «не ваш ход» (`engine.ts:1015`) не должна срабатывать для этих четырёх.
Предложения живут до конца следующего хода адресата; одно активное предложение на пару.

### 9.3. Правила
- **Перемирие** на 3/5/10 раундов: нельзя входить на клетки/стеки другого, стрелять по ним, набегать,
  звать его стеки в совместный удар против него. По истечении — снова война (публичная запись в журнал).
- **Союз**: то же + общий обзор (в `vision.ts visionObservers` добавлять стеки/клетки союзников) +
  союзники могут проходить через клетки друг друга без войск (но не останавливаться).
- **Разрыв с предупреждением**: `breakTreaty` ставит `breakAt = текущий раунд + 1`; до начала следующего
  хода разорвавшего договор действует. Публичная запись «X разрывает союз с Y — война с раунда N».
- **Союзная победа**: если все живые игроки попарно в союзе → `finish` с победителем по очкам,
  остальные союзники получают отметку «союзник-победитель» в итогах (этапы 6–7).
- Дипломатические записи журнала — публичные.

### 9.4. Клиент
Кнопка «🤝» в верхней панели → шторка: список держав (цвет, статус, «до раунда N»), кнопки
«Перемирие на 3/5/10», «Союз», «Разорвать». Входящее предложение — всплывающая карточка «Принять/Отклонить».
На карте у клеток союзников — пунктирная рамка.

### 9.5. Бот
Предложение офлайн-игроку → сообщение «Держава Иван предлагает перемирие на 5 раундов» с кнопками
«Принять / Отклонить» (`callback_query` → `applyAction` от его имени → `pushStateSafe`).

### 9.6. Проверки
`checkTruceBlocksAttack`, `checkTruceExpires`, `checkAllianceSharedVision`, `checkBreakTreatyDelay`,
`checkAlliedVictory`, `checkDiplomacyOff` (действия отклоняются).

## Этап 10. ИИ-соперники (пункт 7)

### 10.1. Игроки-ИИ
- id `ai:<n>`, `Player.ai?: 'easy' | 'normal' | 'hard'`, `connected: true` всегда (офлайн-логика их не трогает),
  уведомления не шлются.
- Лобби: новые `LobbyAction` `addAi {difficulty}` / `removeAi {playerId}` (хост/админы), кнопка «+ ИИ» в
  списке игроков. Меню: «Соло» → выбор «Сам с собой» (старый hotseat) или «Против ИИ» (1–3 соперника,
  сложность) → создаёт комнату, добавляет ИИ, сразу в лобби.
- Партию «человек + только ИИ» разрешить (сейчас `startGame` требует 2 игроков — ИИ считаются).

### 10.2. Логика — `shared/src/ai.ts`
`planAiTurn(view: GameState, aiId): GameAction[]` — **чистая функция**, получает `maskStateFor(state, aiId)`
(ИИ не жульничает с туманом). Сервер применяет действия по одному. Случайность ИИ — свой
`mulberry32(seed ^ round ^ index)`, **не** `nextRandom` (иначе ИИ сдвигает броски боя).

Приоритеты хода (жадная эвристика, пересчитывать после каждого действия):
1. Ответ на события с выбором и дипломатию (принять перемирие, если слабее предлагающего по сумме `armyPower`).
2. **Оборона столицы**: враг в радиусе 3 сильнее гарнизона → найм в столице / подтянуть ближайший стек.
3. **Экономика**: еда < содержание на 2 хода → ферма; есть холмы → шахта; потом рынок, казармы.
4. **Техи**: easy — случайно; normal — экономика → атака → логистика; hard — от ситуации (война → атака/защита).
5. **Найм**: класс, который бьёт самый частый класс увиденного врага (`BEATS`, `units.ts:279`).
6. **Атака**: цели по `battleForecastRatio` (`engine.ts:935`); порог easy 1.6 / normal 1.25 / hard 1.05,
   бонус к ценности за столицу и постройки. Совместный удар соседями — normal/hard.
7. **Залп** по лучшей видимой цели, **каре** против конницы (наполеоника).
8. **Экспансия**: мелкими отрядами на ничейные проходимые клетки.
9. Дипломатия hard: предложить перемирие тому, с кем не граничит, пока воюет с другим; разорвать, когда сильнее.
10. `endTurn`. Страховка: максимум 40 действий; ошибка действия → пропустить эту идею.

Easy дополнительно: 30 % шанс пропустить действие, не использует совместный удар и каре.

### 10.3. Сервер — `server/src/aiRunner.ts`
- После каждого изменения: если текущий игрок — ИИ и прогона нет → запустить.
- Действия с паузой 500–700 мс, каждое через `pushStateSafe(state, {fx})` — люди видят анимацию.
- `pendingSquare`, где защитник ИИ, — решать сразу (в `sweep` и в `aiRunner`).
- После рестарта (этап 2) — перезапустить для всех комнат, где ходит ИИ.

### 10.4. Проверки
- `checkAiFullGame`: 3 ИИ (easy/normal/hard) на карте 10 × 30 раундов — без исключений, партия доходит до
  `finished`, доля отклонённых действий < 10 %.
- `checkAiNoFogCheat`: план ИИ не ссылается на клетки со скрытыми войсками.
- `checkAiHardBeatsEasy`: из 10 сидов hard побеждает easy не реже 7 раз (иначе подкрутить пороги).
